Gitweft

A fast, fully offline Git client for Linux, macOS and Windows.

Download Source on GitHub

Free software under the GPL. No accounts, no telemetry, no update checks.

A Git GUI you can live in

Gitweft shows a repository as a commit graph, lets you stage down to a single line, walks you through merge conflicts and interactive rebases, and keeps an undo history for the local operations that usually make people nervous. It is a native Rust application drawn on the GPU, and it never opens a network connection of its own.

Quick on big histories. Built to stay responsive on a million commits and more: the Linux kernel opens in under three seconds and scrolls at a few milliseconds per frame.

Your computer, your data. No cloud features, no crash reports. The only network traffic comes from git and ssh talking to your remotes, when you ask them to.

Your own git underneath. Hooks, signing, credential helpers, ssh configuration and LFS behave exactly as in a terminal, and the Activity log shows every git command it ran.

What it does

History

A commit graph with colored lanes, branch and tag labels and signature marks. Search by message, author, hash, branch or the content of a change. File history that follows renames, blame, a file browser at any commit, the reflog and dangling commits.

Changes

Stage and unstage whole files, hunks or single lines. Commit, amend, sign off, add co-authors, use commit templates. Stash everything, one file or a selection.

Diffs

Unified or side by side, with word-level highlights, moved lines detected across files, syntax colors, find in the text, and image and Git LFS previews.

Branches and remotes

Fetch, pull and push with progress and a Cancel button. Force pushes use --force-with-lease and --force-if-includes. Drag a commit to cherry-pick it, or a branch onto another to merge or rebase.

Merges and rebases

A merge preview that predicts conflicts, a conflict tool that works per hunk or per line, and an interactive rebase editor: reword, squash, fixup, drop and reorder by drag. Cherry-pick, revert, reset, bisect.

Undo

Undo and redo for local operations: every rewrite records the refs it moved. Discarded changes go to a trash you can restore from, and there are warnings before rewriting commits that are already pushed.

Code review, without a server

Compare any two branches, tags or commits, mark files viewed, comment on lines, see what changed since your last review, and export it as Markdown or a git note.

And the rest

Worktrees, submodules, Git LFS with file locks, shallow and partial clones, tabs, a command palette, full keyboard navigation, dark, light and high-contrast themes, and thirteen languages.

How fast it is

A release build on the Linux kernel's repository: 1,482,850 commits and 96,035 files. Only the rows on screen are drawn, and no git work ever runs on the thread that draws the window.

Opening the repository, with a commit-graph file2.6 s to the first frame
Scrolling the graph3.7 to 4.1 ms per frame (median)
git status55 ms
Laying out a graph of one million commits44 ms

Install

Every package is on the latest release, with SHA-256 checksums and a build attestation you can check with gh attestation verify FILE --repo sorrelfox/gitweft.

SystemPackage
Fedora 44 and laterRPM for x86_64 or aarch64: sudo dnf install ./gitweft-*.rpm
Debian 13, Ubuntu 24.04 and laterDEB for amd64 or arm64: sudo apt install ./gitweft_*.deb
Any Linux distributionAppImage for x86_64 or aarch64, or the Flatpak bundle
macOS 10.15.7 and laterA disk image with one app for Apple silicon and Intel
Windows 10 and 11, 64-bitAn installer that needs no administrator rights, or a zip

Gitweft uses the git you have installed (2.39 or newer). The macOS and Windows builds are new and not signed yet, so each system asks once before opening them. The README has the details, and how to build it yourself.

gitweft ~/code/project               # one tab per repository
gitweft ~/code/project ~/code/other

Offline, and checked

Being offline is a hard requirement of the project, not a setting. The dependency tree has no HTTP or TLS crates, nothing is downloaded at run time (not even a font), and the test suite starts the app with no network and records its system calls to prove it never opens an internet socket. docs/OFFLINE.md explains exactly what is promised and how it is enforced.
